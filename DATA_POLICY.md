# Data Policy - What's Tracked in Git

## Summary

✅ **SOURCE DATA** → Tracked in git
❌ **GENERATED DATA** → Ignored (can be regenerated)

## What's Tracked (in Git)

### ✅ Source/Reference Data
```
data/taxonomy.yaml                    # 12K - Category definitions
data/gazetteer/merchant_aliases.csv   # 6.1K - Merchant mappings
data/few_shot_examples.jsonl         # (if exists) - LLM examples
```

### ✅ Kaggle Downloads (Raw Data)
```
data/raw/bank.xlsx                    # 6.3MB - Kaggle dataset
data/raw/bank_transactions.csv        # 9.9MB - Kaggle dataset
```

**Total tracked data:** ~16MB ✅ Good for git!

**Total ignored data:** ~27MB of generated files

## Regeneration Guide

All ignored (generated) data can be recreated:

### 1. Generate Synthetic Datasets
```bash
python scripts/generate_dataset.py \
  --num-samples 10000 \
  --output data/datasets/synthetic_train.jsonl
```

Creates:
- `data/datasets/synthetic_train.jsonl`
- `data/datasets/synthetic_val.jsonl`
- `data/datasets/synthetic_test.jsonl`

### 2. Prepare Balanced Dataset
```bash
python scripts/prepare_balanced_dataset.py \
  --input data/datasets/synthetic_train.jsonl \
  --output data/balanced/
```

Creates:
- `data/balanced/train.jsonl`
- `data/balanced/val.jsonl`
- `data/balanced/test.jsonl`
- `data/balanced/class_weights.json`

### 3. Label Real Data (from Kaggle)
```bash
python scripts/label_real_data.py \
  --input data/raw/bank_transactions.csv \
  --output data/labeled/
```

Creates:
- `data/labeled/real_transactions_labeled.csv`
- `data/labeled/labeling_summary.yaml`

### 4. Train Model (creates processed data)
```bash
python scripts/train_model.py \
  --train data/balanced/train.jsonl \
  --val data/balanced/val.jsonl \
  --output models/classifier
```

Creates processed data automatically during training.

## Why This Approach?

### ✅ Benefits:
1. **Small repository** - Only ~16MB of source data tracked
2. **Reproducible** - Anyone can regenerate all datasets from source
3. **No duplication** - Generated data isn't committed
4. **Fast clones** - Repository stays lightweight
5. **Version control source** - Track what matters (Kaggle data, taxonomy)

### ❌ What we avoid:
1. Large repository size (would be ~43MB with all data)
2. Redundant files (generated data can be recreated)
3. Merge conflicts in generated files
4. Slow git operations

## What to Commit

✅ **DO commit:**
- Source code changes
- Taxonomy updates (`data/taxonomy.yaml`)
- Gazetteer updates (`data/gazetteer/*.csv`)
- New Kaggle datasets (`data/raw/`)
- Documentation

❌ **DON'T commit:**
- Generated datasets (`.jsonl` files in data/datasets, data/balanced, etc.)
- Trained models (`.pkl`, `.h5` files)
- Logs (`*.log`)
- Cache files (`__pycache__`)

## Questions?

**Q: What if I want to track a specific generated file?**
A: Add it explicitly using `git add -f path/to/file`

**Q: What if datasets become too large?**
A: Use Git LFS or host externally (S3, Google Drive, DVC)

**Q: Can I change this policy?**
A: Yes! Edit `.gitignore` to suit your needs. See `GITIGNORE_GUIDE.md`
